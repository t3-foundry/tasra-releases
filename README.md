# Tasra — build on the network

Tasra is a decentralized key-management platform. Private keys are never assembled: they exist
only as threshold shares held by independent operators, and any use of a key — signing,
decryption, identity-scoped extraction — takes k of n of them cooperating. Who may use a key is
decided by a **rule over verifiable credentials**, not by an access list.

This repository is the distribution channel: the `tasra-cli` binaries, the contract interfaces,
and the **network records** that tell the SDK where a deployment lives. The implementation
repositories are private; everything needed to build against the network is here or on npm.

---

## Start here

```bash
npm install tasra-sdk
```

```ts
import {parsePinnedNetworkManifest, addressBookFromManifest} from 'tasra-sdk/chain'

const base = 'https://raw.githubusercontent.com/t3-foundry/tasra-releases/main/networks/testnet'
const pointer = await (await fetch(`${base}/current.json`)).json()
const text = await (await fetch(`${base}/${pointer.manifest}`)).text()

// Verifies the digest, then every claim in the record.
const manifest = parsePinnedNetworkManifest(text, pointer.sha256)
const addresses = addressBookFromManifest(manifest)   // throws unless the deployment is active
```

That is the whole bootstrap. The manifest is not a convenience file — the SDK **enforces** it:
it re-derives any CREATE2 address and refuses a mismatch, requires code and a deployment receipt
for every contract of an active network, and rejects a service URL that is not `https`.
`addressBookFromManifest` throws for a `planned` or `retired` deployment, so a historical record
can be displayed but can never configure a live client.

## Agent skills

The SDK ships **11 skills** for coding assistants inside the npm package — `tasra-getting-started`,
`tasra-create-slot`, `tasra-dcql-rules`, `tasra-committee-path`, `tasra-sign-and-decrypt`,
`tasra-ibe-identity-scoped`, `tasra-oid4vp-wallet-and-verifier-agent`,
`tasra-credentials-and-sessions`, `tasra-chain`, `tasra-handle-errors`, `tasra-hovi-issuer`.

They are not duplicated here; they arrive with the package:

```bash
ls node_modules/tasra-sdk/skills
```

## The CLI

`tasra-cli` binaries for macOS, Linux and Windows are attached to each
[release](../../releases), with checksums. It registers operators, drives ceremonies, inspects
slots and claims settlement.

## Networks

| | |
|---|---|
| **testnet** | Avalanche Fuji (43113) — `networks/testnet/current.json` |
| **mainnet** | Avalanche C-Chain (43114) — **planned**, no deployment exists |

`networks/testnet/current.json` is the pointer: it names the deployment record and carries its
SHA-256. The record itself lives in `networks/testnet/deployments/`, and the contract interfaces
it references are in `contracts/abi/`.

⚠ **A software release does not activate a network.** The pointer, not a version number, says
what is live. Network records change on their own clock — a service moves, a deployment retires —
so they are updated by **commit**, never as release assets, which are immutable and signed.

### What "active" is claiming

Every contract record carries the runtime code hash observed on chain and the transaction that
deployed it. The records are generated by reading the chain, not written by hand.

⚠ One caveat stated plainly: `AccountantSlashing` is **not byte-reproducible from the current
source tree**. Its source is unchanged, but it is the largest contract in the set and its codegen
is compilation-unit dependent, so unrelated additions to `contracts/src` shifted it. Its ABI is
unaffected and every one of its 70 selectors is present on chain. To source-verify that one
contract, build at the commit it was deployed from.

## Layout

```
networks/     network-profiles.json, and per-network current.json + deployment records
contracts/    abi/<version>/<Contract>.json — the interfaces the records reference
schemas/      network-manifest.schema.json
```

## Status

The testnet is an official testnet and is intended to be built on. It is **not** production:
there is no mainnet and no third-party operators yet. Contracts have not completed an external
audit; treat the network accordingly.
